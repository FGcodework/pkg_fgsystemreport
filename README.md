# FG System Report (pkg_fgsystemreport)

Audit and monitoring toolkit for Joomla, part of the **FG** extension series.

- **Dashboard** – site statistics and a configurable PDF report (download or e-mail).
- **Installed Extensions** – every extension with its available update, quick filters (all / with update / third-party / disabled), grouping, CSV export and a working "Go to update" link.
- **Security Check** – 30+ checks with a site health score: Joomla/PHP/DB versions and end-of-life, `configuration.php` permissions, exposed sensitive files, SSL certificate expiry, Super Users and failed logins, MFA, backups, update sites, known vulnerable extensions (VEL) and more. CSV/JSON export.
- **Security History** – every run is recorded; trend chart (30/90/365 days) and run-to-run comparison.
- **Disk Usage** – the largest folders under the site root (adapted from `mod_jm_treesize`).
- **Icon Classes** – reference of the icon classes available in the admin template.
- **Scheduled notifications** – the companion task plugin runs the Security Check on a schedule, records it in the history and e-mails you only when something got worse.
- Languages: English, Slovak (sk-SK), German (de-DE).

## Installation

Download **`pkg_fgsystemreport_vX.X.X.zip`** from the [latest release](https://github.com/FGcodework/pkg_fgsystemreport/releases/latest) and install it in *System → Install → Extensions*. The package contains:

| Extension | Purpose |
|---|---|
| `com_fgsystemreport` | the component |
| `plg_task_fgsystemreport` | Task Scheduler plugin (security notifications + history); enabled automatically on a fresh install |

Updates arrive through Joomla's normal *System → Update → Extensions* (update server: `updates.xml` in this repository).

After installing, create a task *"FG System Report: Security Check Notification"* under *System → Scheduled Tasks* (e.g. daily) to get history and notifications.

## Repository layout

```
com_fgsystemreport/       component (source of com_fgsystemreport_vX.X.X.zip), incl. CHANGELOG.md
plg_task_fgsystemreport/  task plugin
pkg_fgsystemreport/       package manifest + install script
updates.xml               update server (generated by build.sh)
build.sh                  builds dist/*.zip and regenerates updates.xml
.github/workflows/        release workflow (tag v* → GitHub release with the ZIPs)
```

## Releasing

1. Bump `<version>` in `com_fgsystemreport/fgsystemreport.xml` **and** `pkg_fgsystemreport/pkg_fgsystemreport.xml` (the package version follows the component), update the inner ZIP names in the package manifest, and add an entry to `com_fgsystemreport/CHANGELOG.md`. If the plugin changed, bump `plg_task_fgsystemreport/fgsystemreport.xml` and its ZIP name in the package manifest.
2. Run `bash build.sh` – builds `dist/` and regenerates `updates.xml`.
3. Commit, then `git tag vX.X.X && git push --tags`. The workflow checks that tag, package version and `updates.xml` agree and publishes the release.
